Redis 缓存穿透
击穿、雪崩解决方案

2026 年 8 月 25 日 · redis · cache · 面试

面试被问到 Redis 缓存问题时，很多同学会把这三个概念混在一起讲。它们的成因、影响范围、应对思路其实各不相同，下面按顺序拆开讲清楚。

什么是缓存穿透

缓存穿透指查询一个数据库中根本不存在的数据，缓存和数据库都没有命中，每次请求都会打到数据库上。如果被恶意构造大量不存在的 key 高频请求，数据库压力会被瞬间拉满。

常见的应对方式是缓存空值，或者用布隆过滤器提前拦截明显不存在的 key：

public class CacheService {

    // 布隆过滤器提前拦截不存在的 key
    public Object get(String key) {
        if (!bloomFilter.mightContain(key)) {
            return null;
        }
        Object value = redis.get(key);
        if (value == null) {
            value = db.query(key);
            redis.setex(key, 60, value == null ? "EMPTY" : value);
        }
        return value;
    }
}

什么是缓存击穿

缓存击穿指某一个热点 key 恰好在这一时刻过期，大量并发请求同时穿透到数据库，给数据库造成瞬时压力。跟穿透的区别在于，击穿的 key 本身是存在的、合法的。

常见解法：给热点 key 加互斥锁，只让一个线程去数据库重建缓存，其余线程等待或返回旧值；也可以对热点数据设置永不过期，用异步线程去更新。

什么是缓存雪崩

缓存雪崩指大量 key 在同一时间集中过期，或者 Redis 实例整体宕机，导致请求大规模涌向数据库。应对思路是给过期时间加上随机抖动，避免同时失效；同时对 Redis 做高可用部署（哨兵/集群），降低整体宕机的概率。

工程实践中的取舍

这三种场景在真实系统里往往是叠加出现的，不需要死记硬背概念，理解"谁在什么条件下打到了数据库"这个因果链条，面试时能自己推导出对应方案，比背答案更有说服力。
